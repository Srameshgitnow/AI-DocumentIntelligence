# Repository discoverability guide

This file documents the search and community improvements included in the repository. It is intended to keep future updates consistent and useful rather than encouraging keyword stuffing.

## Target audience

- Developers building document chatbots and private knowledge bases
- Teams evaluating retrieval-augmented generation (RAG)
- Engineers exploring LangChain, embeddings, PostgreSQL, and pgvector
- Contributors looking for a self-hosted AI document Q&A starter project

## Search phrases used naturally

AI document intelligence, AI document Q&A, document chatbot, semantic search, retrieval-augmented generation, RAG application, document embeddings, LangChain PostgreSQL, pgvector, OpenAI document search, and Anthropic Claude document analysis.

## Ongoing content checklist

- Keep the README opening paragraph clear about the problem, supported file types, and technology stack.
- Add setup prerequisites and a tested quick-start path for every new deployment option.
- Document meaningful changes with examples, screenshots, or architecture notes where appropriate.
- Link related issues and pull requests instead of repeating keywords.
- Keep titles and descriptions descriptive, accurate, and readable.
- Share release notes or tutorials that solve a specific document-AI use case.
- Re-test README commands after changes to Docker, environment variables, or package scripts.

## GitHub settings to review

Repository administrators should set a concise repository description, choose relevant topics such as `document-ai`, `rag`, `semantic-search`, `langchain`, `pgvector`, and `typescript`, and add a social preview image that shows the project name and purpose. These settings are managed by GitHub and cannot be changed from repository files.

## Avoid

Do not make unsupported performance, privacy, or accuracy claims. Do not add hidden text, repetitive keywords, fake badges, or links to services that are not configured. Search visibility is most sustainable when the project is useful, documented, maintained, and easy to run.
